  - First explosion: **stage 13** (`max_abs ≈ 3.06e7`)
  - Then grows to `~1e92`, `~1e183`, then non-finite.

3. The first bad Jacobian entry is:
  - `jac_g_x[row=224, col=164] = NaN`
  - Mapped to: `stage 18`, `dynamics[4]` w.r.t. `state[2]`
  - At this point, `x0[164] ≈ 5.316e90`
  - Therefore NaN is caused by **exploded rollout state at x0**, not by clean LLT/auxvar inputs.

4. Objective gradient failure is consistent with the same issue:
  - first bad `grad_f` entry at `col=175` with `x0=NaN`.

Interpretation: the NaN seen by IPOPT is a consequence of an already-invalid initial guess trajectory, generated before optimization begins.

### Where NaN Appears:
- ❌ IPOPT gradient evaluation at stage 50
- ❌ Constraint row 200: Control bound `U - max_u`
- ❌ w.r.t. variable 146: Wing CL Chebyshev coefficient #146

### Root Cause:
**Chebyshev polynomial degree 25 becomes numerically unstable** during IPOPT's automatic differentiation. The recursive formula `T_n = 2*x*T_{n-1} - T_{n-2}` produces extreme intermediate values that, when combined with optimization line searches, cause overflow.
